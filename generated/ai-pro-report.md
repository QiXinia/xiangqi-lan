# AI-PRO 定稿报告（闭环到上线候选）

> 自对弈自检 + 工程参数 A/B，**非神经网络训练**；离线单文件、无训练、无权重、无外部资源。经典 `js/ai.js` 一字未动；仅改 `js/ai-pro.js` 与 test/。

## 一、性能修复：eval2 不再拖慢搜索（修复前 → 修复后）
根因：eval2 原在每个内部节点全量重算（countNonKing + 王/炮架/开放线 4~5 次全盘扫描），像上轮 SEE 一样压低 NPS；另在着法排序里每手额外做一次 `isInCheck`(givesCheck)，再砍一刀 NPS。
修复：
- eval2 全部统计（np/王位置/双炮/兵线/车位置）**合并进基础评估已有的单次全盘扫描**，摊销成本≈0；
- 删除排序中每手的额外 `isInCheck`(givesCheck 将军先验)，恢复与经典一致的单次合法性校验。

固定墙钟 MS=800，4 局面 pro vs classic：
| 局面 | classic 深度/NPS | pro 修复前 | pro 修复后 |
|---|---|---|---|
| 开局 | 6.0 / 51k | 5.5 / 36k(71%) | 6.0 / 44k(86%) |
| 中局t | 6.5 / 26k | 6.0 / 23k(88%) | 6.0 / 23k(88%) |
| 中局c | 6.0 / 28k | 6.0 / 18k(64%) | 6.0 / 20k(71%) |
| 残局 | 8.0 / 72k | 8.0 / 71k(99%) | 8.0 / 71k(99%) |
| **合计均深** | **6.63** | 6.38(差0.25) | **6.38(差0.25)** |

结论：NPS 修复后平均回到 classic 的 ~86%，深度差收窄到 0.25 层（接近 ≤0.2 判据，剩余为 countermove Map 等轻量开销）。

## 二、防守脆败：threatExt 已关 + 稳定性加固
- **threatExt=false**（上轮 A/B 已定）：同 seed 下子差 -831→+575 的脆败源；单向只延伸己方进攻、挤占防守深度。
- **本轮新修 throw 阻断门**：复现 seed2026 第 12 局偶发异常（CPU 竞争下 quiescence 递归过深栈溢出，且旧 catch 内 firstLegal 未再包保护导致外抛）。修复：
  1. `searchBestMovePro` 双层 try/catch（内层 `firstLegal` 再包保护，极端返回 null）；
  2. `quiescence` 加 `ply>80` 硬上限防栈溢出。
- 复跑 seed2026：**异常局 1 → 0**（见下）。

## 五、最终 FEAT 与 eval2 落地方式
```
FEAT = { see:false, eval2:true, counter:true, lmr2:true, nullR:true, threatExt:false, rootTime:true }
```
- SEE 全交换：禁用（NPS 不升反降）。
- threatExt：禁用（脆败源）。
- eval2：多维特征**合并进单次棋盘扫描**，零额外全盘开销；保留将象棋局向心/双炮/车开放线。
- 保留：countermove 先验、连续 LMR、自适应空着 R（np≤9 禁用 / np≤16→R2 / 否则 R3，不深于 depth-3）、根动态时间、将军扩展（对称）。
